# 冠脉 DSA 关键帧第二轮实验

本轮使用本机 `harbin_useful_data` 中的真实 XA DICOM。目录中有 100 个可读头信息的 512×512、MONOCHROME2、未压缩序列。按帧数分层抽取 15 个不同序列，覆盖 34–109 帧。其中 3 个序列运行参数矩阵，每种配置测量两次。另 12 个序列运行五路对比。本轮没有输入逐帧人工参考，结果中的帧一致性以原版 Frangi 为比较对象。

所有方法共用 DICOM 解码、序列级百分位归一化、ROI、充盈区间及候选窗口。真实原始像素为 512×512，主对比缩放至 256×256 后计算。矩阵改变滤波分辨率时继续使用同一充盈区间和同一去重输入。测试在 macOS arm64、Python 3.12.6、scikit-image 0.26.0 的本机环境完成，耗时以实际记录为准，Linux Electron 的端到端性能仍需在目标机器测量。

## Frangi 实现与瓶颈

- 现有默认设置为 sigma `[1, 2, 3]`、固定 gamma `0.03`、暗血管极性和候选区间计算。预处理在整个序列的共享 1–99 百分位下裁剪和归一化。DICOM 读取统一 MONOCHROME 显示极性，分析图像与 Frangi 输出均为 `float32`。已去除输出上冗余的同类型复制。
- 固定 gamma 时，31 个真实候选帧的多尺度输出等于逐尺度响应的逐像素最大值。二维路径每个尺度做五次可分离的高斯导数滤波。sigma=1 在参考库中使用 `truncate=100`，约 143 个核系数，是原版最慢的尺度。分析用例的 31 帧共调用 465 次高斯滤波，剖析中约 83% 的 Frangi 时间落在 Hessian 路径。逐尺度 CPU 时间约为 0.832、0.192、0.221 秒。 [scikit-image 0.26.0 Hessian 源码](https://raw.githubusercontent.com/scikit-image/scikit-image/v0.26.0/src/skimage/feature/corner.py) · [Frangi 源码](https://raw.githubusercontent.com/scikit-image/scikit-image/v0.26.0/src/skimage/filters/ridges.py)
- 新后端使用 OpenCV `sepFilter2D`、短尾高斯核、二维解析特征值和 `float32` 中间图。保留逐尺度最大值与固定 gamma。对于主特征值符号错误的像素显式置零。平滑的反极性条纹测试中，原版在该退化输入上出现强响应，新版在条纹中心按极性抑制。
- 旧流程为报告重算所选帧的响应图。第二轮报告按唯一帧号为每种滤波器生成一次预览图，并单独计入导出。两种 Black-hat 组合共用逐帧响应。优化版缓存高斯核，矩阵另外测量在同一帧、gamma 和极性下复用公共尺度响应的收益。

## 时序筛选与失败状态

按充盈区间平滑融合评分，再寻找局部峰值。应用最小帧距和相似度过滤，并优先给不同窗口保留候选。局部帧差扣除整帧中位亮度偏移，显影变化单独记录。稀疏光流通过往返一致性、残差及最少跟踪点数检查。显影变化过快或特征不足时，光流值为空且状态可在 CSV 中查看。运动扣分使用可信段内的平滑位移，未知帧取有效样本的中位惩罚。

有 DICOM 帧时间并观察到至少三个间距稳定的低运动极值时，算法划分疑似周期窗口。其他情况下保留原充盈区间。没有有效充盈区间或候选响应过低时，输出空候选与明确失败原因。提供逐帧人工标注后，输出 Top-1、Top-3、Top-K 命中与到可接受帧和首选帧的距离。

## 真实序列结果

| 方法 | 滤波 CPU 均值 | 首选帧同原版 | 完整候选及顺序同原版 |
|---|---:|---:|---:|
| Contrast + Frangi | 1.5789 s | 15/15 | 15/15 |
| Contrast + Sobel | 0.0101 s | 4/15 | 0/15 |
| Contrast + Black-hat 9×9 | 0.0170 s | 8/15 | 4/15 |
| Contrast + Black-hat 9×9 + Motion | 0.0170 s | 9/15 | 3/15 |
| Contrast + OpenCV Frangi | 0.1994 s | 15/15 | 15/15 |

同尺度优化版在 15 个序列上的完整候选及排序均与原版相同，滤波阶段平均加速 **7.9 倍**。像素审计覆盖 31 帧、2,031,616 个像素。最终优化版的平均绝对误差为 `1.87e-08`，最大绝对误差为 `7.75e-07`。合成亮条纹中心的原版暗极性响应为 0.971，优化版暗极性响应为 0.000，优化版亮极性响应为 0.971。

五路合跑的核心墙钟时间平均 2.182 秒。共享阶段的 CPU 均值分别为 解码 0.026 秒、预处理 0.122 秒、充盈检测 0.117 秒、时序稳定性 0.139 秒。表内滤波时间包括生成响应和统计，不含共享阶段、矩阵和报告导出。单独运行 `sample_092` 的 71 帧序列，各方法测量三次，从解码到选帧的 CPU 均值为 Contrast + Frangi 1.613 秒、Contrast + OpenCV Frangi 0.508 秒、Contrast + Sobel 0.357 秒、Contrast + Black-hat 9×9 0.367 秒、Contrast + Black-hat 9×9 + Motion 0.370 秒。这些数值为本机实测，运行期间未独占 CPU。

Sobel 的滤波开销最低，但仅 4/15 的首选帧与 Frangi 一致。Black-hat 9×9 的首选帧有 8/15 一致，值得作为轻量候选方案继续评估。运动扣分改变了 11/15 个序列的候选或顺序，其中 6/15 的首选帧改变。检测到疑似周期分窗的序列有 1 个。候选区间内，光流可估计 518 帧，显影变化过快 23 帧、跟踪不足 5 帧、缺少同区间前一帧 35 帧。运动权重是否改善选帧，需要逐帧人工参考验证。

## 参数矩阵

三例矩阵覆盖 52、71 和 91 帧，使用相同归一化及候选区间。三尺度为 `[1,2,3]`，两尺度为 `[1,2]`。全帧配置改变计算范围，排名仍仅使用充盈候选。下表每组记录两次，先按序列求均值，再按配置跨序列求均值。

| Frangi 配置 | 原版滤波 CPU | 优化版滤波 CPU | 优化版候选排序同 256 三尺度原版 |
|---|---:|---:|---:|
| 256 · 3 尺度 · 候选帧 | 1.7242 s | 0.2110 s | 3/3 |
| 256 · 2 尺度 · 候选帧 | 1.3972 s | 0.1298 s | 3/3 |
| 512 · 3 尺度 · 候选帧 | 7.0306 s | 0.9376 s | 0/3 |

512 像素处理时，三个序列的首选帧较 256 像素原版均后移一帧。保持 256 像素且去掉第三尺度在矩阵三例中保持候选顺序。该结论的覆盖范围是三例参数实验。

| Black-hat 核 | 滤波 CPU | 首选帧同 256 三尺度原版 |
|---|---:|---:|
| 5×5 | 0.0090 s | 1/3 |

同时计算 `[1,2]` 与 `[1,2,3]` 时，每帧将五次尺度计算合并为三次，复用实验的平均 CPU 从 0.337 秒降为 0.204 秒。表中的单配置计时独立运行，分别记录完整滤波开销。

38 项自动化测试通过，覆盖极性、固定 gamma、多尺度复用、背景掩膜、运动不确定状态、周期保留、人工标注、原始文件不变及现有网页接口。

## Electron / OpenCV C++ 迁移

优先评估 **Contrast + Black-hat 9×9**。它可以直接使用 `morphologyEx`，在本轮的无标签实验里比 Sobel 更接近 Frangi 的首选帧。**256×256 三尺度优化 Frangi** 保留为候选一致性对照，可用 `sepFilter2D` 和二维特征值公式迁移。Sobel 可以直接映射到 `Sobel` 和 `magnitude`，适合作为轻量对照。运动模块还需要 `goodFeaturesToTrack`、`calcOpticalFlowPyrLK` 和不确定状态处理。核宽、sigma 和 ROI 都使用分析图像像素坐标，迁移时需固定预处理尺度并核对输出。

运行命令与标注格式见 [README](../README.md#第二轮算法对比)。原始输出索引为 [参数矩阵](../outputs/round2_matrix_final/summary.json)、[扩展五路对比](../outputs/round2_comparison_final/summary.json)、[Frangi 像素与性能审计](../outputs/round2_frangi_audit.json) 和 [初始流程性能基线](../outputs/round2_legacy_baseline.json)。真实序列的图像和响应图保存在本地报告目录。
