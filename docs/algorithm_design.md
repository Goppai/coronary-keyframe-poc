# 算法设计与边界

## 可独立替换的模块

`dicom_reader` 严格解码并返回白名单技术元数据；`preprocessing` 保留分析图与展示图；`algorithms/*` 计算单项特征；`scoring` 融合；`selector` 执行时序与相似度约束；`pipeline` 编排、计时；`report` 导出静态结果；`evaluation` 处理参考标签；`benchmark` 记录CPU/RSS。

## 本项目自行设计的启发式

1. 共享序列采样百分位缩放；轻度高斯去噪，CLAHE默认关闭。
2. 参考背景：前N帧中位数，或其中最低相邻差异帧，或在暗化不足时缓慢更新。暗化均值 `mean(max(reference-current,0))` 构成充盈代理，不等同于造影剂浓度；另保留绝对差分。
3. 高斯时序平滑；原始动态范围低于阈值则拒绝；相对5–95百分位归一化、阈值分段、最短区间过滤，可保留多段。confidence仅为动态范围的有界启发式，未经校准。
4. 候选帧上计算多尺度 Frangi/Sato；Frangi gamma固定并记录在配置中，不逐帧自动估计；保存响应均值、阈值面积和两者乘积。增强图不是分割真值。滤波尺度单位为处理图像像素，更改处理尺寸要重新检查尺度。
5. 轻度去噪后的 Laplacian 方差和 Sobel 能量；可在整张处理ROI或血管响应掩膜内统计。噪声和增强伪影仍会影响指标。
6. 相邻绝对差与前后向一致性过滤的 Lucas–Kanade 稀疏跟踪位移；位移除以图像对角线。点数单独输出；零跟踪点不能理解为静止。首帧运动记0为无前驱占位。该指标混有心脏、导管、设备位移及造影剂亮度变化，不能分离为心脏运动量。
7. 两种增强评分各自相对归一化后平均为V，充盈为C，两种清晰度归一化平均为Q，光流归一化为M；`S=wV*V+wC*C+wQ*Q-wM*M`。相对归一化可能放大弱信号，充盈原始动态阈值与血管响应下限只是基础防护。
8. 区间内局部极大值（含边界、平台中点），多区间优先，然后分数排序、最小帧距、Pearson相关过滤。K是上限，不强制补足。相似度可能把不同投影/运动情况下的有效候选滤掉。

这些步骤不是声称复现任何单篇论文。权重与阈值为初始实验值，必须在开发集调整后在独立病例测试集冻结评价。

## 性能与移植

NumPy归一化、直方图、OpenCV高斯/Laplacian/Sobel/稀疏LK、时间序列阈值、选择逻辑适合C++ OpenCV移植。Frangi/Sato原型依赖scikit-image，应独立实现尺度归一化Hessian与特征值响应，并用固定像素输入对照数值，不能假设OpenCV有等价内置实现。

Linux Electron优先考虑C++后台进程或Node原生模块配合Worker Threads：避免阻塞UI，便于限制并发内存。Worker Threads本身不加速Python或替代Hessian实现。WASM可承载OpenCV及自实现Hessian，但DICOM解码器、线程/共享内存支持、拷贝与大序列内存需专项测试。Python阶段仅作为验证原型，不要求客户机安装Python作为最终方案。

可行的混合路线：CPU充盈检测先筛选帧段，现有模型只对候选推理；需测量被过滤掉的医生可接受帧比例及端到端耗时。当前未连接任何原生产系统，也没有现有模型耗时/质量基线，不能量化替代收益。

## 已知未解决的工程边界

全序列解码、float32归一化及全尺寸展示图会保留多个数组；1024×1024×200的内存开销显著，不是流式实现。后续应引入分块解码、两遍统计和仅对选中帧生成展示图，并重新测量内存。MONOCHROME极性统一不能涵盖所有减影/后处理编码；像素padding、遮光边缘、嵌入文字和特殊展示LUT尚未自动分离，应使用ROI并人工检查。

`contrast_only` 模式仍记录清晰度和运动指标，阶段计时可识别这部分开销；总时间不是仅充盈函数耗时。单次报告的增强缩略图导出会额外计算Frangi/Sato，用于可视对比，不纳入核心算法计时，导出耗时另列。报告没有隐式声称缩略图计算为零成本。
